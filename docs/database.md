# Database and lifecycle

PostgreSQL is the deployment database. SQLite is the local/test fallback configured by `DATABASE_URL`. SQLAlchemy 2 sessions parameterize values. `backend/app/models/entities.py` defines the schema; `backend/migrations` and `backend/alembic.ini` manage initialization. Run `python -m backend.app.cli init` before serving. The first migration freezes explicit table, foreign-key and index operations; subsequent schema changes must add migration revisions rather than editing deployed history.

Customers and accounts use synthetic string identifiers, with an account-to-customer foreign key. Transactions have unique transaction IDs, account references, indexed timestamps/channel and numeric amounts. Canonical synthetic attributes live in JSON for reproducibility. Predictions have a unique transaction reference, model-version foreign key, indexed operational score/band, and JSON containing frozen feature values and explanations. Models store artifact references, training metadata, metrics and explicit active status.

Cases combine an alert and investigation record one-to-one with a transaction; this avoids a redundant alert/case join in this bounded product. Notes and append-only application audit events reference cases. Assignment, status and disposition history lives in audit events rather than separate duplicated state tables. Users hold a role and salted scrypt password hash. Pipeline runs store configuration, timing, accepted/rejected/duplicate counts and failure details. Quarantined records reference the responsible run and retain a reason.

All application timestamps are UTC ISO-8601 strings, preserving portability between PostgreSQL and SQLite. Transaction IDs prevent replay duplication. Customer/account referential mismatch is quarantined. PostgreSQL foreign keys and case row locks enforce references and serialize investigator changes. API roles protect audit creation and mutation; database-level append-only policies are not yet installed. Provision a separate migration principal and a restricted runtime principal before real deployment.

Model artifacts use trusted local joblib files; never load files supplied by an untrusted user. Back up the database and artifact volume together. Retired models remain available so existing explanations remain reproducible. Deletion requires an explicit retention plan: export required audit records, check prediction references, then remove expired data through reviewed migrations/administration. No automatic destructive retention task is enabled.

To run integration tests on PostgreSQL, set `TEST_DATABASE_URL` to a **dedicated empty test database** then run `python -m pytest backend/tests`. The suite applies Alembic migrations and writes users, synthetic transactions and cases; never point it at a live or shared database. Without that environment variable tests use a fresh temporary SQLite database.
