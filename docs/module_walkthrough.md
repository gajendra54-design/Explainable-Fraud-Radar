# Backend module walkthrough

`core/config.py` reads environment variables and an optional local `.env`. It selects the database, artifact storage, allowed CORS origins and optional alert-score override. No credential is committed. Missing production JWT secret fails startup; CLI bootstrap rejects passwords shorter than twelve characters.

`db/session.py` creates SQLAlchemy sessions and enables SQLite foreign keys. `models/entities.py` defines persisted entities. Alembic initializes them before the API serves traffic. Database connection or migration failures make readiness fail. API integration tests execute the migration and relational workflows on SQLite or an explicitly supplied PostgreSQL test database.

`schemas/requests.py` validates canonical transactions, case actions and pipeline requests. Amounts must be finite and positive, timestamps timezone-aware and historical, country/currency formats supported, and identifiers bounded. Batch ingestion retains raw rejected rows and validation reasons. Tests exercise negative amounts, future timestamps, missing fields and duplicate rows.

`security/auth.py` hashes passwords with independent random salts using scrypt and compares hashes in constant time. Signed expiring JWTs identify users; current database roles decide permissions. `api/routes.py` applies analyst/investigator/administrator authorization and a login attempt limiter. Authentication, role denial, ownership checks and SQL-injection-like search inputs are tested. Tokens should be used only over HTTPS; the frontend stores them in memory.

`services/pipeline.py` generates synthetic records, invokes `ml.FraudEngine`, persists its versioned artifact, validates/ingests canonical transactions, stores reproducible predictions and creates cases. Run metadata captures accepted/rejected/duplicate counts and duration. Failure records survive rollback of the data transaction. Replaying transaction IDs creates no duplicates. The first seed becomes active; later model versions require explicit activation. `services/jobs.py` stores fenced execution leases and retry attempts in the database. `worker.py` polls durable queued runs independently of the API. A PostgreSQL advisory lock serializes claims, heartbeats renew ownership, and final persistence checks the lease under a row lock. Expired leases are recoverable after process crashes; stale workers cannot commit. Bounded retries capture failures, and replayed transaction IDs remain idempotent. SQLite uses a write lock for local verification.

`api/routes.py` reads database state for the dashboard/explorer and uses stored predictions for investigation. `/score` queries strictly earlier account history, excluding the current transaction. Evaluation and drift use the active model's held-out data, separate from investigator opinions. Model rollback does not rewrite historical explanations. A case follows New → Assigned → Under Review → Escalated or Resolved; escalation can return to review. Each change appends an audit event atomically. PostgreSQL row locks serialize state changes, and repeated identical state actions are idempotent.

`main.py` mounts routes, restricted CORS, structured request logs, sanitized error envelopes, request IDs, health/readiness and Prometheus counters. Counters are process-local; failed-login throttling and session revocation use shared database state. Unexpected errors produce a request ID and generic client message without exposing credentials or a traceback.

`cli.py` exposes migration/bootstrap, seed/train/score and user creation. User passwords come from environment variables. The Docker entrypoint initializes the database then starts a nonroot API process. ML-specific generation, chronological features, model fitting, explanation and monitoring are documented in `ml_methodology.md` and implemented under `ml/`.

The integration tests trace a generated record into a database prediction, verify attribution and metrics, claim an alert, add a note, resolve it and inspect immutable audit history. Additional tests cover escalation/reassignment, duplicate actions, unknown labels and missing-model readiness. See `testing.md` for executed evidence and platform limitations.
